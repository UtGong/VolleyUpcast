# Architecture

The app runs entirely in the browser. GitHub Pages serves only the static build over HTTPS; media processing remains browser-local. `src/model.js` is the typed, deterministic domain layer; `src/motion.js` solves template skeletons and coach constraints; `src/mannequin.js` generates body surfaces; `src/render.js` projects them and the court; `src/media.js` handles built-in clip readiness; `src/app.js` owns UI state, review, file/recording lifecycle, and browser persistence. `server.mjs` serves only static files on loopback and has no upload endpoint. The CSP disallows external connections and remote scripts.

## Scenario v1

A scenario has a stable ID, schema version, content revision, actors, contacts, ball classification, tactic fields, editable transcript, clock mapping, observations, calibration intervals, and documented branch conditions. `examples/*.json` show the complete wire format. Serialization is stable for a given scenario; no random IDs or current dates are generated. New observation IDs derive from revision and count.

An important field is `{value, status, source, range?}`. Position paths carry provenance as a unit; each contact component carries independent provenance. Observation records explicitly contain `status: observed`; they are normalized source-image facts, not 3D estimates. Calibration validity is separately stored; a landmark is not a solved camera. Media bytes remain outside JSON. Source text is a human-readable evidence pointer, not verified evidence.

Video time maps to rally time via `rally = video − videoOffset`. Speech time maps via `rally = speech − speechOffset`. Animation rate scales preview playback; it does not rewrite contact times. Declared FPS controls requested video seeks. After clock changes, observation rally timestamps are recomputed from source video time. Recorded audio playback has independent controls and aligns on rally scrubbing. Exact speech-token alignment is a future adapter.

## Rendering

World x runs across the 9m court and z runs longitudinally from −9m to +9m. y is height; the net lies at z=0 with a fixed 2.43m top. `drawScene` performs camera-basis transforms and a pinhole perspective divide on actual x/y/z coordinates. It draws an articulated, explicitly labelled human template with simple gait/arm/jump phases. There is no imported mocap or biomechanics claim. This CPU Canvas renderer needs no WebGL dependency.

Each actor uses a timed polyline. Ball segments share exact contact anchors; each segment uses two easing curves from endpoint height to the chosen mid-time peak and back. Endpoints are continuous, velocity/acceleration generally are not. This is a tactical illustration, not a projectile solver. Contact proximity, time order, numeric ranges, basic model limits, rough horizontal speed and net crossing checks detect supported contradictions. These tests cannot certify a physically possible or regulation-legal rally.

Descriptive slide fields are kept visible even when not executable: takeoff/landing text, technique, coverage instruction and branches are coach intent. Numeric path/contact editors govern travel and ball anchors. Only the explicit cue vocabulary described below controls body motion; arbitrary transcript prose is not compiled into animation.

## Articulated motion and body volume

Optional `motion.version: 1` data extends scenario v1 with stable actor rigs and source-linked pose keys. Every rig dimension and pose parameter has field provenance. A key identifies its actor/event, rally time, influence span, phase, foot-plant mode, parameters, depth interpretation and optional source video time/observed image joints. Older scenes have no required migration; missing newer rig dimensions receive explicit approved illustrative defaults when edited.

`skeletonAt` combines deterministic approach/dig/set/attack/block/landing phases with keyframe constraints. Two-bone inverse kinematics preserves upper/lower limb lengths; infeasible targets are reported rather than silently treated as measurements. Facing uses shortest-angle interpolation, and planted feet retain their anchor across compatible keys. Contact-owning attack templates use the shared contact target. Validation catches supported unreachable hands, hand/contact height disagreement, planted jumps/translation, abrupt turns, bad parameter ranges and frame-clock contradictions. It does not solve collisions or certify natural whole-body mechanics.

`buildMannequin` constructs tapered body surfaces, joint volumes, head/facial hints, palms/thumbs and shoes from the skeleton and fifteen dimensions. Painter-depth sorting draws projected faces using CPU Canvas. Close-up views show one actor with more geometry; the full court uses lower detail. Fingers are coarse shapes without independent joints. No mesh, estimator, external asset, measured anatomy or paid model is used. Capture targets 30fps, but actual export cadence depends on browser/device rendering load.

The cue interpreter handles a deliberately small deterministic set: higher hands, wider blocking arms and left/right turns. It creates a cloned candidate, lists changes and any shared contact adjustment, then requires coach confirmation. Ambiguous cues such as “block wiser” produce clarification choices without modifying the scene. Staged form edits invalidate a stale preview. Preview approval never substitutes for scene/export approval.

Source-image joint annotations are normalized observed 2D points with player/frame identity. A conditional arm fit uses shoulder/elbow/wrist segment directions, source aspect ratio and a coach-chosen vertical-plane orientation to set shoulder/elbow angles. Its explicit `imageFit` field retains the plane assumption; it is not a camera/depth solve or automatic detector. These angles drive fixed-length 3D limbs and export, with contact anchoring taking precedence. Foreshortening, hidden depth and missing joints remain unmeasured. The UI reports observed coverage and requires explicit depth acceptance. The packaged synthetic clip retains the earlier body template and supplies timing/contact reference only; the new body geometry is not a measured reconstruction of its joints.

Additional optional pose parameters control shoulder flexion/abduction, elbow flexion/bend plane, forearm twist, torso twist, swing influence and compression. Older keys use template defaults for missing parameters. Template jump phases use a bounded illustrative parabola, countermovement compression, landing compression and damped recovery; this is not an identified spring-mass system or measured center of mass. The pelvis is a visual proxy. Airborne-to-ground key interpolation delays foot planting until lift is near zero.

`videoBinding` separates unbound local media from an explicit manual illustration. A new clip deletes prior sample/motion/evidence and freezes its placements; unbound state blocks every export mode and renders no demo actors. Unknown manual scaffold contacts do not animate ball/jump templates. For files up to 128MiB, a local content hash verifies a saved clip before reconnecting it; different bytes require replacement. Hashes and annotations persist in private scene JSON, never a remote upload. Media itself remains a blob outside JSON.

The UVG-VCM reference is independently licensed CC BY4.0, resized to a small 720p fixture with attribution/change notes and a byte manifest. Its manual 1.50–2.70s excerpt models two anonymous players and explicitly uncertain contact windows/3D placements; it is not the full 10s rally or automatic reconstruction. The exporter carries source scope, clocks and attribution. Private uploaded validation footage and its derived QA stay in ignored storage and are not static-build inputs. See [video reconstruction protocol](VIDEO_RECONSTRUCTION.md) for the unimplemented estimator interface.

## Review and export

Content mutations snapshot undo history, increment revision, clear review and export approval, recompute derived clock mappings, update both views, then store the draft. Undo/redo/import clear approval, even if serialized input claimed approval. Done editing marks a revision reviewed. Confirm requires that exact revision. Final mode rejects unresolved/inferred critical fields; illustrative mode permits explicit uncertain finite values while rejecting structural/continuity errors. Intentionally flexible spin or joint detail need not be invented. Critical motion cannot bypass review by being labelled not applicable.

`MediaRecorder(canvas.captureStream(30))` records the actual rendered scene in real time. The exporter checks approved revision, blocks content mutations, discards interrupted exports, labels the interpretation on the canvas, and emits a real silent WebM. Export duration is wall-clock rally duration, independent of preview animation rate. No audio mixing, transcoding, or server-side rendering is included.

The first export frame is drawn at rally zero before capture begins. An unconfirmed motion preview blocks review/confirmation/export. Built-in sample loading waits for successful nonempty HTTP media and video decoding, reports loading/success/error, and focuses its workspace. The static build gives all local JS imports and CSS the same deterministic content hash to avoid stale mixed module graphs after deployment.

## Boundaries

Schema parsing rejects unknown versions and malformed essential structures. Type checking currently covers the domain model, not the entire UI. localStorage is same-origin browser storage, not encrypted vault storage. Keep sensitive notes out of demonstrations. The static server uses a root containment check. Production authentication, multitenancy, uploaded-media management, remote collaboration, paid inference are outside this prototype. The public GitHub Pages deployment adds no server-side data processing or media-upload endpoint.

## Selected-player local inference

`focus-ui.js` manages a single anonymous target, source interval, sparse identity taps, cancellable jobs, local voice notes and unconfirmed corrections. `inference-client.js` decodes source frames and sends cropped ImageBitmaps to a dedicated MediaPipe CPU/WASM worker. It begins at a coach anchor and traverses forward/backward at requested 20 Hz; browser timestamp seeking is not exact frame-index decoding. Near-duplicate detections are suppressed, horizontal identity jumps are rejected, and long losses need another anchor. This geometric association is not a trained identity tracker and must be inspected.

Scenario v1 optionally includes `performance.version:1`: stable actor ID, labelled selection/interval/seeds, raw source-normalized 33-point proposals and model world points, per-frame visibility/state/gap, model artifact hash, estimated fixed rig, explicit projection basis and a separate coach correction list. `videoBinding.state="focused"` requires that track, matching clocks and zero invented ball contacts. Schema, finite bounds, source order, bone and interval constraints are checked. Final export always remains blocked by inferred depth; explicit illustrative review is required. Replacing a clip deletes this track. Edits revoke approval; Undo/import cannot restore trusted approval.

`focus.js` interpolates only short contiguous valid spans. `focus-render.js` renders just this player on a neutral stage. Source-image directions drive fixed-bone retargeting; model Z is damped and bounded. Root movement is a projection proxy, not calibrated court travel/jump height. Other players, ball, floor contacts, exact fingers and physical accuracy are not reconstructed. A 2D/model alignment residual is self-consistency only, never ground-truth accuracy.

Speech uses a separate local Transformers.js/ONNX CPU worker with quantized Whisper tiny.en. Local model paths and remote-disabled settings are explicit; CSP permits self-hosted workers/WASM, and `connect-src 'self'` prohibits external services. No remote ASR fallback or upload endpoint exists. Invalid/short/silent audio fails explicitly; returned text remains editable and unverified. A small deterministic cue parser proposes hand-height or timing variations; ambiguity asks one question. The source observations are retained unchanged. Main-thread UI remains responsive and cancellation terminates workers.

`models/manifest.json` records source versions, integrity, transfer budget and served-file hashes. Third-party licenses accompany redistributed assets. Static build includes only index/src/examples/vendor/models; private QA and recordings are excluded.
